## Проблема

У Вордстата нет точки входа. Пользователь попадает на главный экран, видит поле
«Введите запрос» — и не знает, что вводить. Google Trends решает это витриной:
готовые тренды видны сразу, до всякого ввода. У Вордстата такой витрины нет.

`wordstat-trends` показывает тренды сразу: что растёт, что сезонное, что падает.

## Текущее состояние

Прототип: исследовательское ядро и инфраструктура сбора. Сквозной витрины
(«зашёл — увидел тренды») ещё нет — это фазы роадмапа, они не закрыты.

**Что уже работает** (CI зелёный, 176 тестов):

- сборочный сервис `wordstat_trends.collect_service` — суточное расписание и
  HTTP-эндпоинт (`POST /collect`, `GET /status`) с блокировкой параллельного
  запуска;
- ядро краткосрочных сигналов `wordstat_trends.short_term` — недельный
  профиль и детекция всплесков методом leave-one-week-out
  ([`docs/SHORT_TERM.md`](docs/SHORT_TERM.md));
- исследования: сезонность на дневных окнах (#34, #32), комбинированный
  вектор фраз (#23), эксперимент «D» — протоколы и результаты в `docs/`
  (`ISSUE_23_COMBINED_VECTOR.md`, `ISSUE_32_SEASONAL_STRUCTURE.md`,
  `ISSUE_34_WINDOW_THRESHOLD.md`, `EXPERIMENT_VECTOR_D.md`), скрипты в
  `scripts/`, фикстуры в `tests/fixtures/`;
- контейнер сбора для Dokku (`deploy/`): Chrome с CDP, профиль на томе,
  суточный цикл — развёртывание в [`docs/DEPLOY.md`](docs/DEPLOY.md);
- CI-гейт «без LLM» (`scripts/check_no_llm.py`).

**Чего нет:** витрины (фаза [#14](https://github.com/axisrow/wordstat-trends/issues/14))
и сквозного пути от сбора до опубликованной страницы: прогон моделей по
живому датасету и сборка статики на GitHub Actions ещё не настроены.

**Что ограничивает движение к продукту — объём данных, а не код.** Собранных
дневных рядов меньше десяти фраз, длинного месячного ряда для sp=12 нет.
Upstream-блокеры сбора закрыты
([wordstat-cli#2](https://github.com/axisrow/wordstat-cli/issues/2) —
устойчивость прогона, [wordstat-cli#29](https://github.com/axisrow/wordstat-cli/issues/29) —
`DownloadTimeoutError`), но непрерывный сбор ещё не развёрнут и не проверен:
открыты [#50](https://github.com/axisrow/wordstat-trends/issues/50) (deploy
key в коммите результатов) и [#51](https://github.com/axisrow/wordstat-trends/issues/51)
(импорт cookies в Chrome-профиль).

## Принцип: без LLM, только классический ML

Обёртка вокруг чужого LLM-API не демонстрирует инженерных навыков — ни работы с
признаками, ни валидации, ни понимания природы данных.

Это не вкусовое предпочтение. [Анализ ниши](https://github.com/axisrow/wordstat-cli/blob/main/docs/REFERENCES.md)
— 28 публичных Wordstat-проектов — показывает, что классического ML нет ни у
одного инструмента сбора, а «интеллект» двух платформ сводится к вызову LLM с
промптом. Место классического ML свободно.

- Прогноз — `sktime` (ETS/Theta), а не «спроси у модели, вырастет ли спрос»
- Кластеризация — эмбеддинги + k-means, а не «сгруппируй эти фразы»
- Тренды — статистика отклонения от сезонного прогноза, а не оценка LLM

**Каждое число воспроизводимо**: его можно пересчитать и получить то же самое.
Ответ LLM невоспроизводим по природе — это аргумент против него именно здесь, а
не только вопрос сложности.

LLM допустим за пределами пайплайна, но ни одно число, ни один кластер, ни один
тренд не получаются его вызовом.

Принцип охраняется механически: CI-гейт (`scripts/check_no_llm.py`) валит
сборку, если в дереве зависимостей (`uv.lock`) появился LLM-клиент —
`openai`, `anthropic`, `langchain`, `gigachat` и другие (issue
[#4](https://github.com/axisrow/wordstat-trends/issues/4)).

## Как устроено

Целевая схема; что из неё уже смёржено — см. «Текущее состояние» выше.

```
Dokku (по расписанию)                      GitHub
  контейнер: Chrome + профиль на volume
  wordstat-cli собирает           ->  репо wordstat-trends
  ML: тренды и прогнозы           ->  Actions: сборка статики
  коммит результатов              ->  Pages
```

Сбор данных вынесен в [wordstat-cli](https://github.com/axisrow/wordstat-cli) —
CLI, работающий через CDP к уже авторизованному Chrome, без API-ключей и
биллинга. Здесь остаются ML и витрина.

## Данные

По [справке Яндекса](https://yandex.ru/support2/wordstat/ru/interface/new):
история с января 2018, окно одного запроса до пяти лет, дневная детализация
только за 60 дней. Горизонт моделирования — месячные ряды до ~100 точек со
склейкой двух окон.

Формат сырого CSV «Динамики» (заголовки, разделители, кодировка) и проверка
границы истории по факту, а не по цитате — в [`docs/DATA.md`](docs/DATA.md).
