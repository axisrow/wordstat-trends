# MVP #23 — вектор AutoETS, вариант Б

Это только проверка гипотезы, не продуктовая реализация.

## Предрегистрация второй итерации: дневной `sp=7`

Этот раздел записан **до получения и просмотра дневных фикстур**. Пороговые
значения ниже не будут подбираться по результату.

### Вход и парсинг

- Каждая фикстура должна содержать ровно 59 реальных последовательных дней:
  `2026-06-23` → `2026-08-20`. Первые 56 дней (`2026-06-23` → `2026-08-17`)
  образуют обучающее окно из 8 полных недель; последние 3 дня остаются
  контролем вне обучения.
- `Период` разбирается отдельно от месячного формата, строго как
  `datetime.strptime(value, "%d.%m.%Y")`; русский текстовый месяц здесь не
  применяется.
- Сохраняется механика реального экспорта: UTF-8 с BOM, CR-only через
  `splitlines()`, разделитель `;`, пробелы тысяч удаляются, десятичная запятая
  заменяется точкой.
- До fit проверяются длина 59, точные границы, уникальность и возрастание без
  пропущенных дней. Для 56-дневного обучающего окна отдельно проверяется
  распределение наблюдений по дням недели `[8, 8, 8, 8, 8, 8, 8]` в порядке
  пн … вс. Недостающие дни не достраиваются. Начало окна не обязано быть
  понедельником: кратность семи уже обеспечивает равное число всех дней недели.

### Вектор и сопоставление окон

Одинаково для окон 56, 49 и 42 дня (8, 7 и 6 полных циклов) строится
`AutoETS(auto=True, sp=7, n_jobs=1, random_state=0)`. Спецификация ETS не
задаётся вручную. Для каждого fit фиксируются выбранные error/trend/seasonal.
Сезонные состояния выравниваются по дням недели **пн … вс**, а не по позиции в
окне.

Чтобы сравнивать аддитивную и мультипликативную спецификации в единой шкале,
сезонный профиль переводится в безразмерный множитель спроса `p[d]`:

- multiplicative: `p[d] = s[d] / mean(s)`;
- additive: `p[d] = 1 + (s[d] - mean(s)) / abs(level)`;
- no seasonality: `p[d] = 1` для всех дней.

Здесь `level` — финальное фильтрованное состояние соответствующего fit.

### Заранее заданный критерий устойчивости

Для каждого укороченного окна профиль сравнивается с полным. Обозначим
`A = max(p_full) - min(p_full)` и `delta = p_short - p_full`.

Здесь амплитуда `A` — именно **peak-to-trough размах нормализованного профиля**:
`max(p_full) - min(p_full)`. Порог `0,05` означает размах в 5 процентных
пунктов относительно среднего множителя `1`; это не отношение `max/min` и не
СКО относительно уровня.

Неплоский профиль (`A >= 0,05`) считается устойчивым, только если одновременно:

1. корреляция Pearson по 7 коэффициентам `corr >= 0,90`;
2. относительный RMSE коэффициентов
   `sqrt(mean(delta^2)) / sqrt(mean((p_full - 1)^2)) <= 0,25`;
3. максимальный сдвиг относительно амплитуды
   `max(abs(delta)) / A <= 0,35`.

Все три условия должны пройти **и для 49, и для 42 дней у каждой фразы**.
Смена наличия сезонной компоненты между окнами автоматически означает провал
устойчивости, даже если численные метрики случайно проходят.

Пороги оставлены без изменений: они заданы в относительных единицах профиля и
не обосновывались числом циклов. Самое короткое окно содержит шесть полных
циклов, то есть втрое больше минимальных двух для сезонной инициализации
statsmodels.

Если полный профиль плоский (`A < 0,05`), корреляция и деление на малую
амплитуду не интерпретируются: он заранее классифицируется как неосмысленный
для гипотезы недельного вектора. Для прозрачности численные значения всё равно
выводятся как `N/A`, а не заменяются нулём.

### Отдельный вопрос: оправдана ли сезонность

Второй backend — автоматический ETS из statsforecast с `season_length=7`; его
спецификация также не фиксируется руками. Эта кросс-проверка отвечает не на
вопрос устойчивости вектора, а на самостоятельный вопрос: оправдана ли
сезонная компонента вообще.

Для каждого окна и backend будут отдельно записаны:

- автоматически выбранная спецификация, включая наличие сезонности;
- AIC/AICc выбранной модели и, когда backend предоставляет кандидатов, значения
  лучшей сезонной и лучшей несезонной модели вместе с разностью критерия;
- Pearson и `max(abs(p_statsforecast - p_sktime)) / A_sktime` между профилями,
  когда оба backend выбрали сезонность и сравнение определено.

Согласие backend **не является критерием прохождения**. Если один backend
отверг сезонность, будет указано, какой именно, по какому информационному
критерию и с какими числами. Такое расхождение — самостоятельный измеренный
результат, а не успех или провал эксперимента и не повод вручную выбирать
спецификацию.

Провалом гипотезы считается неустойчивость по трём заранее заданным метрикам
выше либо плоский полный профиль (`A < 0,05`), в котором нечего различать.

Перед вычислительным прогоном потоки ограничиваются:

```bash
export OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 NUMEXPR_NUM_THREADS=2
```

## Первая итерация (месячные, `sp=12`) — отрицательный результат

Дата прогона: 2026-08-21. Исходная воспроизводимая реализация этой итерации
зафиксирована в commit `d5bcead`; текущий скрипт переведён на дневную вторую
итерацию.

### Протокол

- Источник: три реальные CSV-фикстуры по 24 месячных наблюдения, август 2024 —
  июль 2026.
- Чтение: UTF-8 с BOM, CR-only разбивается через `splitlines()`, `;`, русский
  текстовый месяц, пробелы в числе запросов удаляются.
- Модель: `sktime.forecasting.ets.AutoETS(auto=True, sp=12, n_jobs=1,
  random_state=0)`; Python 3.12.10, sktime 1.1.0, statsmodels 0.14.6.
- Вектор фиксированной длины: финальный фильтрованный уровень, финальный тренд
  (`0`, если AutoETS выбрал модель без тренда), затем последние фильтрованные
  сезонные состояния для января … декабря. Состояния привязаны к календарному
  месяцу, а не к позиции в окне.
- Для устойчивости тот же расчёт должен быть выполнен после удаления последних
  3 и 6 месяцев. Заранее заданный предел заметного дрейфа — 20% для уровня,
  тренда и относительной L2-нормы сезонного профиля.
- Стоп-условие: если укороченные векторы не получены или выходят за пределы,
  проверка осмысленности профилей не выполняется.

### Что измерено

### Загрузка данных

Каждая фикстура разобрана в 24 последовательных месячных значения без пропусков:
начало `2024-08`, конец `2026-07`. Контрольная точка сезонной фикстуры:
декабрь 2024 = `1 234 632` запросов.

### Векторы полного окна

Порядок сезонных коэффициентов во всех строках: **янв, фев, мар, апр, май,
июн, июл, авг, сен, окт, ноя, дек**.

| купить телефон | M,N,M | 1 229 347,969 | 0,000 | 692,206 | 0,8288; 0,7244; 0,7533; 0,6944; 0,6825; 0,8495; 0,9993; 1,0000; 0,9056; 0,9087; 0,9049; 0,9541 |
| курсы английского языка | M,N,M | 44 198,919 | 0,000 | 579,831 | 0,9755; 0,9039; 0,8847; 0,8474; 0,9695; 0,9738; 0,9266; 1,0000; 1,5240; 1,1542; 1,1314; 0,9448 |
| новогодние подарки | M,A,M | 135 779,868 | -3 118,438 | 649,150 | 1,0459; 0,3044; 0,2083; 0,1689; 0,1589; 0,1368; 0,2137; 0,2799; 0,6301; 1,3916; 2,8275; 7,2577 |

`M,N,M` означает multiplicative error, no trend, multiplicative seasonality;
`M,A,M` — multiplicative error, additive trend, multiplicative seasonality.

### Главная проверка устойчивости

Результат одинаков для всех трёх профилей:

| Окно | Наблюдений | Конец окна | AutoETS `sp=12` | Численное сравнение с полным окном |
|---|---:|---:|---|---|
| полное | 24 | 2026-07 | вектор получен | база сравнения |
| минус 3 месяца | 21 | 2026-04 | ошибка | невозможно |
| минус 6 месяцев | 18 | 2026-01 | ошибка | невозможно |

Точный результат всех шести укороченных запусков:

```text
ValueError: Cannot compute initial seasonals using heuristic method with less
than two full seasonal cycles in the data.
```

Полученные численные пары для метрик дрейфа: **0 из 6**. Поэтому значения
`level_relative`, `trend_relative` и `seasonal_relative_l2` отсутствуют, а не
равны нулю.

### Вывод

**MVP на имеющихся фикстурах не подтверждает состоятельность вектора.** 24 точки
— ровно два полных цикла `sp=12`, то есть минимальный объём, на котором AutoETS
вообще получил сезонную инициализацию. После обязательного усечения остаётся 21
или 18 точек, и модель не строится. Следовательно, устойчивость вектора численно
не проверена; использовать его как представление спроса и переносить идею в
продукт по этому результату нельзя.

Это отрицательный/неопределённый результат по стоп-условию, а не свидетельство
устойчивости или неустойчивости коэффициентов. Для честного повторения нужен
более длинный месячный ряд из #6: как минимум 30 точек, чтобы после удаления
6 месяцев осталось два цикла; практически лучше несколько полных циклов сверх
этого минимума.

### Чего проверить не удалось

- Численный дрейф векторов при усечении: укороченные векторы не существуют.
- Осмысленность: сравнение декабрьского пика «новогодних подарков» с более
  плоским профилем «купить телефон» **не выполнялось**, потому что главная
  проверка не прошла.
- `sp=7` и дневные данные не рассматривались.
