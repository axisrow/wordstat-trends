# Деплой контейнера сбора на Dokku

Инфраструктура Фазы 0 ([#8](https://github.com/axisrow/wordstat-trends/issues/8)):
постоянно живущий Chrome с CDP, авторизованный в Яндексе, и `wordstat-cli`,
который раз в сутки собирает сотни фраз с паузами между ними и коммитит
результаты в репозиторий.

Сбор **не может жить в GitHub Actions**: раннеры одноразовые, авторизованного
Chrome там нет, а учётные данные в секреты не кладём — это путь к капче и
нарушение принципа проекта. Actions только публикуют статику, реагируя на
коммиты этого контейнера.

## Цикл витрины: коммит результатов → пересборка Pages (issue #107)

Замыкает Фазу 5: новые данные сами становятся новой витриной, без ручных
шагов и без секретов в Actions.

1. **Коммит артефакта.** После прогона ранжирования в репозиторий
   `wordstat-trends` коммитится JSON-артефакт витрины по фиксированному пути
   `site_data/showcase.json` (схема `showcase/v1`, см.
   `src/wordstat_trends/showcase.py`). Артефакт нового прогона **заменяет**
   предыдущий — каталог хранит только актуальное состояние, история версий
   живёт в git. `site_data/` не исключается `.gitignore` (за этим следит
   тест `test_default_artifact_path_in_tracked_site_data`).
2. **Пересборка.** Push в `main` запускает `.github/workflows/pages.yml`;
   шаг сборки передаёт путь артефакта в `scripts/build_site.py
   --artifact site_data/showcase.json`. Скрипту нужен только stdlib
   (i18n-форматтеры дат и чисел), зависимости проекта в Actions не
   ставятся, облако не скрейпится — всё берётся из коммита.
3. **Публикация.** Деплой-токен выдают `actions/configure-pages` /
   `actions/deploy-pages`; секретов у workflow нет и быть не должно
   (Pages на репо включается оператором: Settings → Pages → Source:
   GitHub Actions).
4. **Нет артефакта / нет фраз.** Файла ещё нет (до первого коммита
   результатов) или `phrases` пуст — сборка не падает: витрина выходит в
   пустом состоянии (#21 п.7). Дата данных на странице трендов —
   `generated_at` артефакта, отформатированный i18n-форматтером локали;
   это возраст данных, а не дата сборки. Битая схема артефакта — ошибка
   сборки: публиковать «данных нет» поверх существующих данных нельзя.

Проверка цикла без деплоя — юнит-тесты сборки в
`tests/test_site_i18n.py` (пустое состояние и витрина из тестового
артефакта, в том числе по пути по умолчанию).

## Состав

| Файл | Назначение |
|---|---|
| `deploy/Dockerfile` | Chrome (chromium из debian), Python 3.12, зависимости из `uv.lock` |
| `deploy/entrypoint.sh` | старт Chrome с CDP на `127.0.0.1`, запуск сервиса сбора |
| `src/wordstat_trends/collect_service.py` | суточный цикл сбора, коммит результатов, HTTP-эндпоинт запуска (issue #24) |
| `src/wordstat_trends/cookies_import.py` | импорт cookies.txt в Chrome-профиль + проверка авторизации при старте (issue #51) |
| `scripts/upload_cookies.sh` | заливка cookies на хост по SSH, прямо в том |

## Развёртывание

CDP должен быть доступен **только изнутри контейнера**; единственное, что
может публиковаться наружу — узкий HTTP-эндпоинт запуска (раздел ниже).

```bash
# на хосте Dokku
dokku apps:create wordstat-collector

# том: профиль Chrome, cookies, фразы, результаты, git-репозиторий и ssh-ключ
sudo mkdir -p /var/lib/dokku/data/storage/wordstat-collector-data
sudo chown 1000:1000 /var/lib/dokku/data/storage/wordstat-collector-data
dokku storage:mount wordstat-collector /var/lib/dokku/data/storage/wordstat-collector-data:/app/data

# По умолчанию портов наружу нет; эндпоинт запуска публикуется отдельно
# (см. «Запуск сбора по требованию»).

# Рестарт-политика: entrypoint сам завершается с ошибкой, если Chrome умер
# посреди прогона или CDP не поднялся — контейнер должен подняться заново.
dokku ps:set wordstat-collector restart-policy on-failure:10

git remote add dokku dokku@<host>:wordstat-collector
git push dokku main
```

Деплой — это `git push dokku`; редеплой не трогает том, профиль переживает
перезапуск.

### Подготовка тома

```bash
# список фраз (по одной на строку, # — комментарий)
scp phrases.txt dokku@<host>:/tmp/phrases.txt
ssh dokku@<host> "sudo install -o 1000 -g 1000 -m 644 /tmp/phrases.txt \
    /var/lib/dokku/data/storage/wordstat-collector-data/phrases.txt"

# git-репозиторий результатов + машинный ключ с правом записи (deploy key)
ssh dokku@<host>
sudo -u 1000 git clone git@github.com:axisrow/wordstat-data.git \
    /var/lib/dokku/data/storage/wordstat-collector-data/repo
# Ключ — ВНЕ рабочего дерева репозитория (issue #50): сервис делает `git add .`
# в repo/, ключ внутри repo/ попал бы в коммит и уехал в origin.
sudo install -o 1000 -g 1000 -m 600 machine_key_ed25519 \
    /var/lib/dokku/data/storage/wordstat-collector-data/.ssh_key
# и указать ключ в repo/.git/config через core.sshCommand:
#   ssh -i /app/data/.ssh_key -o StrictHostKeyChecking=accept-new
```

Ключ живёт на томе (рядом с `repo/`, но не внутри), а не в образе и не в
`dokku config`. Дополнительно к размещению вне дерева `collect_service`
исключает путь `.ssh_key` перед `git add` (и вычищает его из индекса, если он
был добавлен ранее) — защита не полагается только на расположение файла.

**Если ключ уже уехал в origin**: вычистка индекса (`git rm --cached`) убирает
ключ только из будущих коммитов — история остаётся, а репозиторий
`wordstat-data` доступен в рамках GitHub. Правильная процедура после такого
инцидента — **ротация ключа**, а не только вычистка: см.
[#58](https://github.com/axisrow/wordstat-trends/issues/58). Полный цикл
(проверка истории → генерация нового ключа → регистрация на GitHub → отзыв
старых → установка на том → проверка push) автоматизирован скриптом
`scripts/rotate_deploy_key.sh <dokku-host> <app-name>`.

### Cookies

Единственный путь — по SSH с машины оператора:

```bash
scripts/upload_cookies.sh dokku@<host> wordstat-collector cookies.txt
```

Скрипт кладёт файл в том с правами `600`/uid 1000 и перезапускает контейнер.
Cookies **не кладутся** в образ, в переменные окружения и не печатаются в логи.

**Формат** — Netscape cookies.txt (выгрузка расширений «cookies.txt», curl):
7 полей через TAB — `domain  tailmatch  path  secure  expires  name  value`,
`#HttpOnly_`-префикс для httpOnly-кук. Файл больше 1 МиБ или не являющийся
корректным UTF-8 отклоняется.

**Импорт при старте (issue #51).** Файл на томе — не «лежит мёртвым грузом»:
при каждом старте контейнера, до запуска `wordstat collect` (и до подъёма
HTTP-эндпоинта), сервис:

1. читает `/app/data/cookies.txt` и парсит только куки доменов Яндекса
   (`yandex.ru`, `ya.ru`, `yandex.com`, `yandex.net` и поддомены) — остальное
   в файле игнорируется, сторонние сессии контейнеру не нужны;
2. устанавливает их в Chrome-профиль через CDP `Storage.setCookies` — точечно,
   по ключу (name, domain, path), не трогая чужие куки; импорт идемпотентен;
3. открывает Wordstat и тем же probe, что живой сбор, подтверждает
   авторизацию (страница входа = неудача).

Любая неудача на этом пути — **fail closed**: сервис завершается, контейнер
уходит в рестарт по политике, сбор не стартует. Это заметно в `dokku logs`
строкой `импорт cookies не удался: ...` — исправьте файл и перезапустите.
В лог попадают только счётчики и домены, никогда имена и значения кук.

Файла нет — контейнер работает с уже авторизованным профилем на томе
(уставший persistent-профиль остаётся отдельным случаем: протухание такой
сессии ловит сам `wordstat collect`, как и раньше). Сессионные куки без
expiry не переживают перезапуск Chrome, но переимпортируются из файла при
каждом старте — держите файл на томе, пока он нужен.

## Доступ к CDP — только изнутри

`entrypoint.sh` стартует Chrome с `--remote-debugging-address=127.0.0.1
--remote-debugging-port=9222`. Порт не публикуется (`EXPOSE` — только
декларация; маршрута и проброса портов у приложения нет). Открытый наружу
отладочный порт авторизованного Chrome — это вся сессия Яндекса любому, кто до
него дотянется, поэтому доступ возможен только через `dokku run`:

```bash
dokku run wordstat-collector curl -s http://127.0.0.1:9222/json/version
```

Отдельная задача [#24](https://github.com/axisrow/wordstat-trends/issues/24)
(после мержа #8) добавит узкий HTTP-эндпоинт запуска сбора — он не проксирует
CDP и принимает один POST со списком фраз.

## Запуск сбора по требованию — HTTP-эндпоинт (issue #24)

Расписание остаётся основным режимом; эндпоинт **дополняет** его. Инициатор
сбора и место сбора — не одно и то же: наружу торчит одна операция вместо
полного управления браузером.

`entrypoint.sh` после старта Chrome запускает
`python -m wordstat_trends.collect_service` — один процесс, в котором живут
суточный планировщик и HTTP-интерфейс с **общей блокировкой**: запрос при
активном сборе (включая плановый прогон) получает `409`, а не второй Chrome.

Наружу доступны ровно две операции (`0.0.0.0:${TRIGGER_PORT}`):

```bash
# запуск: только POST, только явный список фраз (≤ TRIGGER_MAX_PHRASES)
curl -X POST https://<host>/collect \
    -H "Authorization: Bearer ${TRIGGER_TOKEN}" \
    -H "Content-Type: application/json" \
    -d '{"phrases": ["купить слона", "продать слона"]}'

# статус: состояние, фразы текущего/последнего прогона, счётчики
curl https://<host>/status
```

- **Аутентификация** — `Authorization: Bearer <TRIGGER_TOKEN>`, токен живёт в
  `dokku config` (секрет Actions), не в репозитории и не в образе. Без
  `TRIGGER_TOKEN` HTTP-часть не поднимается вовсе (fail closed), расписание
  работает.
- **Всё, кроме этих двух операций, — 404/405/401.** CDP не проксируется,
  произвольные команды браузеру не принимаются.
- **Результаты наружу не отдаются** — как и в расписании, они попадают в
  репозиторий коммитом машинным ключом.
- **Логирование**: каждый вызов пишется в лог контейнера — кто (IP), когда,
  какие фразы. Токен не логируется никогда. При компрометации токена это
  единственный способ понять объём проблемы — см. `dokku logs`.

Публикация порта (по решению оператора, только если нужен запуск извне):

```bash
dokku config:set wordstat-collector TRIGGER_TOKEN="$(openssl rand -hex 32)"
dokku ports:add wordstat-collector http:80:8899
dokku ps:restart wordstat-collector
```

## Диагностика

```bash
dokku logs wordstat-collector --tail 100   # ход сбора; фразы печатаются, cookies — никогда
dokku run wordstat-collector curl -s http://127.0.0.1:9222/json/version   # жив ли CDP
dokku ps:report wordstat-collector
dokku run wordstat-collector ls /app/data/results   # что накопилось
```

- **Chrome не поднялся / CDP не готов за 60с** — entrypoint завершает контейнер;
  смотрите `dokku logs`, затем запускайте `chromium` руками через `dokku run`.
- **`импорт cookies не удался`** — файл на томе не разобрался или не прошёл
  проверку авторизации (fail closed, issue #51). Смотрите текст после двоеточия:
  номер строки с ошибкой формата, «страницей входа» (сессия в файле протухла) —
  перезалейте файл (раздел «Cookies» выше). Контейнер в это время рестартует
  по политике `on-failure:10`.
- **Прогон упал на середине фразы** — wordstat-cli#2 (устойчивость прогона:
  инкрементальный манифест и дозапись) закрыт, повторный запуск продолжает
  сбор с места остановки, а не начинает с нуля. Расписание продолжает
  работать.
- **Wordstat показывает страницу входа** — `wordstat collect` сам прекращает
  работу; это сигнал, что сессия протухла — обновите cookies (раздел выше).

## Настройки окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PHRASE_DELAY_S` | `30` | пауза между фразами, сек (главный «предохранитель» от капчи) |
| `COLLECT_INTERVAL_S` | `86400` | пауза между суточными прогонами |
| `CDP_PORT` | `9222` | порт CDP внутри контейнера (слушает `127.0.0.1`) |
| `COOKIES_FILE` | `/app/data/cookies.txt` | ПУТЬ к Netscape cookies.txt на томе; файл есть — импорт при старте (issue #51), нет — работа с профилем тома |
| `PHRASES_FILE` | `/app/data/phrases.txt` | список фраз |
| `RESULTS_DIR` | `/app/data/results` | выгрузки `wordstat collect` |
| `GIT_DIR` | `/app/data/repo` | git-репозиторий для коммита результатов |
| `TRIGGER_TOKEN` | — | токен HTTP-эндпоинта (issue #24); не задан — эндпоинт отключён |
| `TRIGGER_PORT` | `8899` | порт HTTP-эндпоинта внутри контейнера |
| `TRIGGER_MAX_PHRASES` | `50` | лимит списка фраз в одном запросе |
| `GRAPH_ENABLED` | `0` | обход графа запросов (issue #82): расширение словаря от seed-набора по рёбрам `top_related` |
| `GRAPH_STATE_FILE` | `/app/data/graph_state.json` | файл персистентного состояния обхода (словарь, фронтир, суточный бюджет) |
| `GRAPH_DAILY_BUDGET` | `10` | суточный бюджет НОВЫХ фраз из графа (поверх seed-прогона) |

RESULTS_DIR и GIT_DIR — разные каталоги: перед коммитом сервис копирует
накопленные выгрузки из RESULTS_DIR в `GIT_DIR/results` и только затем делает
`git add`/commit/push (issue #57). Дополнительной ручной раскладки не нужно.

Меняются через `dokku config:set wordstat-collector PHRASE_DELAY_S=60` и
перезапуск. Переменных с учётными данными нет и быть не должно — исключение
ровно одно: `TRIGGER_TOKEN` (токен запуска, не учётные данные Яндекс-сессии),
он живёт в `dokku config` и никогда не попадает в образ или репозиторий.

## Обход графа запросов: runbook (issue #82)

Обход расширяет словарь от seed-набора (`PHRASES_FILE`) по рёбрам
«похожих запросов»: каждый плановый прогон после сбора seed-фраз добавляет
до `GRAPH_DAILY_BUDGET` новых фраз из фронтира (приоритет — частотность
ребра `top_related`, затем глубина от seed; потолки — глубина 2 и 1000 фраз)
и раскрывает собранное. Состояние живёт в `GRAPH_STATE_FILE` на томе:
перезапуск контейнера не начинает обход заново и не теряет прогресс,
суточный бюджет переживает рестарт внутри дня. HTTP-запросы `/collect`
граф не трогают — только плановые прогоны.

**Замер роста словаря по дням** (на томе):

```bash
# текущее состояние: словарь, фронтир, бюджет
jq '{дата: .budget.date, словарь: (.visited | length), фронтир: (.frontier | length), потрачено_бюджета: .budget.spent}' /app/data/graph_state.json

# динамика по дням — новые фразы дня это новые run-каталоги в коммитах результатов
git -C /app/data/repo log --since='2 weeks' --format='%ad %s' --date=short -- results
```

Состояние — один перезаписываемый файл, собственной истории у него нет;
дневную динамику удобно фиксировать внешним cron'ом с тем же `jq` (значение
`словарь` монотонно растёт). Пока `фронтир > 0` и `потрачено_бюджета =
GRAPH_DAILY_BUDGET`, расширение упирается в бюджет (норма); `фронтир = 0` —
тематика исчерпана в пределах лимитов глубины/объёма.

**Остановка расширения без остановки seed-сбора**:

```bash
dokku config:set wordstat-collector GRAPH_ENABLED=0
```

Seed-прогон продолжает собираться и коммититься как раньше; состояние обхода
сохраняется на томе, повторное включение `GRAPH_ENABLED=1` продолжает обход
с того же фронтира. Полный сброс словаря — удалить `GRAPH_STATE_FILE`
(осознанное решение: битый/чужой файл состояния обход не молча перезаписывает).

**Куда смотреть при проблемах.** `GET /status` → `last_error`: ошибки чтения
состояния и продвижения обхода попадают туда, не роняя seed-сбор.
