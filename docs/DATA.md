# Данные: что реально отдаёт Вордстат

Этот документ фиксирует **факт**, а не пересказ справки Яндекса. Он основан на
трёх прогонах `wordstat-cli collect --keep-raw` против живого
`https://wordstat.yandex.ru/` (не тестовый стенд, не документация — сырой CSV,
скачанный из авторизованного интерфейса) и на ручной проверке селектора дат
в браузере.

Дата замера: 2026-08-21. Аккаунт: обычный аккаунт Яндекса, без API/биллинга —
как описано в `wordstat-cli/README.md`. Регион для всех трёх фраз: «Россия».

## Прогон

Три фразы разного профиля, все с `--region "Россия" --keep-raw`:

| Фраза | Профиль | Прогон (UTC) |
|---|---|---|
| «купить телефон» | высокочастотная | `2026-08-21T01:40:38Z` |
| «курсы английского языка» | среднечастотная | `2026-08-21T01:41:44Z` |
| «новогодние подарки» | сезонная | `2026-08-21T01:41:55Z` |

Каждый прогон произвёл четыре представления — `top_popular`, `top_related`,
`dynamics`, `regions` — как `.parquet` (типизированный) и `.csv` (сырой,
благодаря `--keep-raw`).

## Представление «Динамика» (`dynamics`)

Это представление, на которое опирается весь роадмап (склейка окон,
прогнозирование). Дословный факт по всем трём прогонам:

### Заголовок (дословно, с BOM)

```
﻿Период;Число запросов;Доля от всех запросов, %;Динамика частотности запросов «<фраза>», по месяцам, 01.08.2024 — 31.07.2026, Россия, все устройства
```

Четыре поля, разделённые `;`. Четвёртое называется длинным текстом заголовка
графика («Динамика частотности запросов «<фраза>», по месяцам, ...») — но это
**не мусор без данных**: это настоящая четвёртая колонка CSV, и в каждой из
24 строк данных она присутствует как пустое поле после последней `;`.
Смотри дословный пример строк ниже — обрати внимание на завершающую `;` в
конце каждой строки.

Фикстура `["Период", "Показов"]` из тестов `wordstat-cli` (репозиторий
[wordstat-cli](https://github.com/axisrow/wordstat-cli)) была синтетической и
**не совпадает** с реальностью: колонка называется `Число запросов`, не
`Показов`, и полей четыре (с пустым четвёртым), а не два.

### Формат периода

`август 2024` — **русское название месяца текстом плюс год**, разделённые
пробелом. Это **не** `"01.2024"`, как написано в README `wordstat-trends`, и
не ISO-подобный формат. Разбор периода должен парсить русские названия
месяцев, не даты.

### Число строк и гранулярность

24 строки в каждом из трёх прогонов — **ровно 24 месяца**, дефолтное окно
`wordstat-cli` (оно не передаёт диапазон дат в URL, полагается на дефолт
интерфейса). Гранулярность в этом замере — месяц («По месяцам» — опция
интерфейса, выбранная по умолчанию при первом открытии вкладки «Динамика»,
это видно на скриншоте селектора). Селектор «По месяцам» показывает
раскрывающийся список рядом с ним — судя по справке Яндекса, там есть и «По
неделям»/«По дням», но сам список **не открывался** в этом замере, так что
точный набор опций и формат периода для недельной/дневной детализации —
**не проверено**, а взято по справке. Если задачи склейки/загрузчика будут
работать с недельной или дневной гранулярностью, это нужно замерить
отдельно.

### Формат чисел

- Разделитель полей: **`;`** (точка с запятой), не запятая.
- Десятичный разделитель: **запятая** — `0,0115`, не точка.
- Разделитель тысяч в «Число запросов»: **обычный ASCII-пробел** (`997 977`,
  байт `0x20`), не неразрывный пробел (проверено побайтово — это важно
  отличать от того, как числа могут отображаться скопированными из веб-UI,
  где неразрывный пробел встречается чаще) и не запятая.
- Проценты — тоже с запятой как десятичным разделителем: `0,0115` означает
  0.0115%.

### Кодировка и переводы строк

- **UTF-8 с BOM** (`EF BB BF` в начале файла).
- Переводы строк — **только `CR` (`\r`, `0x0D`)**, без `\n`. Не CRLF и не
  голый LF. Файл технически валиден как «одна строка» для наивных ридеров,
  которые ищут `\n`.
- `wordstat-cli` читает файл через `str.splitlines()` (не через `csv` модуль
  напрямую на сырых байтах), поэтому CR-only не ломает парсинг — но любой
  код, который берёт файл руками (`grep`, построчное чтение без
  `splitlines()`), увидит один гигантский «файл в одну строку».

### Наличие «Доли от общего числа запросов»

Присутствует, под названием **«Доля от всех запросов, %»** (не «Доля от
общего числа запросов», как в тексте issue) — третья колонка, число с
запятой как разделителем, например `0,0115` (проценты).

### Пример строк (дословно, сезонная фраза «новогодние подарки»)

Заголовок (одна строка, четыре поля, четвёртое — длинный текст заголовка
графика):

```
Период;Число запросов;Доля от всех запросов, %;Динамика частотности запросов «новогодние подарки», по месяцам, 01.08.2024 — 31.07.2026, Россия, все устройства
```

Строки данных (каждая заканчивается на `;` — четвёртое поле пустое во всех
24 строках, это не опечатка):

```
август 2024;36 806;0,00042;
сентябрь 2024;87 798;0,00095;
октябрь 2024;211 226;0,00202;
ноябрь 2024;509 976;0,00472;
декабрь 2024;1 234 632;0,01106;
январь 2025;173 625;0,00158;
```

Пик в декабре (перед Новым годом) в ~34 раза выше минимума (июнь,
`21 899`) — годовой сезонный цикл виден в сырых данных без какой-либо
обработки.

Полная выгрузка (24 строки, как её отдал Вордстат, включая BOM и CR-only
переводы строк) для всех трёх фраз — в `tests/fixtures/`:
[`dynamics_seasonal.csv`](../tests/fixtures/dynamics_seasonal.csv) («новогодние
подарки»), [`dynamics_high_freq.csv`](../tests/fixtures/dynamics_high_freq.csv)
(«купить телефон»),
[`dynamics_mid_freq.csv`](../tests/fixtures/dynamics_mid_freq.csv) («курсы
английского языка»).

## Граница истории — открытый вопрос №2 эпика закрыт

Справка Яндекса утверждает «с января 2018», некоторые SEO-блоги — «с 2021».
Проверено вручную в интерфейсе (не через CLI — он не даёт выбрать диапазон):
на вкладке «Динамика» открыт селектор периода и продавлен назад по годам до
упора.

**Факт: в селекторе дат 2018 год — самый ранний доступный, все 12 месяцев
2018 года выбираемы, при переходе к 2017 стрелка «назад» блокируется.**
Данные за январь 2018 реальны (не заглушка/ноль): для фразы «купить телефон»
январь 2018 — `952 634` запроса. **Справка Яндекса права, SEO-блоги про
2021 — нет.**

Шаги воспроизведения (занимают ~30 секунд): открыть
`https://wordstat.yandex.ru/?words=<фраза>`, вкладка «Динамика», клик по
селектору диапазона дат (показывает текущее окно, например «Август 2024 —
Июль 2026»), в открывшемся календаре клик по стрелке «назад» рядом с годом
столько раз, сколько нужно — на 2018 году стрелка становится неактивной
(серой). Все 12 месяцев 2018 года при этом выбираемы.

Побочная находка: при выборе одного месяца (январь 2018) интерфейс сам
расширяет диапазон и показывает сообщение «Диапазон дат был изменён:
минимальный период для построения графика с выбранной детализацией — три
календарных месяца». Это ограничение интерфейса, а не данных — при
месячной детализации минимальное окно, которое можно запросить, три месяца.

Максимальная длина окна одного запроса («до пяти лет» по справке) в этом
замере не перепроверялась вручную до упора — сам факт нижней границы
(январь 2018) для задач склейки важнее и закрыт. Если склейка окон
(следующая задача Фазы 0) упрётся в длину окна, это стоит перепроверить
отдельно.

## Представления «Топы запросов» — открытый риск, не решённый здесь

`top_popular` и `top_related` вернули **0 строк данных** во всех трёх
прогонах — только заголовок, без единой строки запроса, при том что то же
самое окно интерфейса (`https://wordstat.yandex.ru/`, вкладка «Топы
запросов», раздел «Популярные») **визуально показывает данные** при ручной
проверке в браузере для той же фразы («купить телефон»): список из
«купить телефон», «какой телефон купить», «купить телефон самсунг» и т. д.
с ненулевыми числами запросов.

Значит несовпадение — не в том, что Вордстат не отдаёт эти данные, а в
скачанном CSV конкретно из `wordstat-cli`: файл `top_popular.csv` физически
заканчивается сразу после строки заголовка (проверено побайтово, файл не
обрублен на середине). Похоже на гонку между командой «скачать» и
готовностью таблицы, либо на другой URL/состояние страницы в момент клика
по кнопке скачивания для этих двух представлений. **Это не входит в объём
данного issue** (он про формат `dynamics`), но должно быть заведено как
отдельный баг в `wordstat-cli` до того, как на `top_popular`/`top_related`
будет что-то строиться.

## Представление «Регионы» (`regions`), для справки

Формат совпадает с `dynamics` по разделителям/кодировке. Заголовок:

```
Регион;Число запросов;Доля от всех запросов, %;Индекс интереса (аффинити-индекс), %;<заголовок графика>
```

950 строк для «купить телефон», 813 для «курсы английского языка», 765 для
«новогодние подарки» — число строк зависит от фразы (не фиксировано), в
`regions` данные есть (в отличие от `top_popular`/`top_related`).

## Источник фактов

- Полные прогоны (все четыре представления — `top_popular`, `top_related`,
  `dynamics`, `regions` — как `.parquet` и `.csv`) сохранены локально в
  `~/Projects/wordstat/wordstat-output/runs/20260821T01*` (не в этом
  репозитории). В `tests/fixtures/` вынесен только `dynamics.csv` каждой из
  трёх фраз — представление, на которое опирается склейка окон и
  загрузчик.
- Проверка границы истории — ручная, через интерфейс `wordstat.yandex.ru`,
  скриншоты не сохранялись (сессия временная), но результат
  детерминирован: селектор дат — часть интерфейса, а не результат запроса,
  его состояние можно перепроверить в любой момент повторно.
