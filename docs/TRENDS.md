# Детекция аномального роста (Фаза 3, Б1 — issue #83)

Скор аномальности месячного ряда: отношение факта последних месяцев к
прогнозу сезонного наива (`seasonal_naive`, `to_monthly_series` из
`src/wordstat_trends/forecasting/baseline.py`). Отдельная библиотека
детекции аномалий не используется — принципиальное решение проекта
(docs/REFERENCES.md, «Позиция проекта»): скор из прогноза интерпретируем,
дёшев и не тянет зависимость.

## Метод

1. Ряд фразы приводится к месячному `pd.Series` (`to_monthly_series`).
2. Хвост ряда длиной `SCORE_WINDOW` месяцев — окно скоринга; всё, что
   раньше, — обучающая история.
3. Сезонный наив обучается на истории и прогнозирует `SCORE_WINDOW`
   месяцев вперёд: прогноз месяца = значение ровно 12 месяцев назад.
4. Скор = средний факт окна / средний прогноз окна.

Скор нормирован относительно собственной истории фразы, а не популяции:
высокочастотная стабильная фраза даёт скор ≈ 1 и не является трендом,
низкочастотная растущая — кандидат.

## Предрегистрация параметров (до прогона на данных)

Объявлены до прогона на фикстурах, не подбирались по результату:

- `SCORE_WINDOW = 3` — окно скоринга в месяцах. Обоснование: 1 месяц
  шумен (разовый всплеск месяца #22 даёт ложный сигнал), окно 6+
  месяцев размывает старт роста — к моменту подтверждения рост уже
  виден и так.
- `GROWTH_RATIO_THRESHOLD = 1.5` — порог «рост есть». Сезонный наив на
  стабильном ряде даёт отношение ≈ 1; порог 1.5 означает устойчивое
  превышение фактом сезонного уровня в 1,5 раза на всём окне — на
  слуховом уровне «в полтора раза чаще, чем год назад».
- `MIN_HISTORY = 24` — минимальная длина ряда: два полных сезонных цикла,
  меньше — сезонному наиву не с чем сравнивать.

Синтетическая проверка в тестах: стабильный сезонный ряд даёт скор ≈ 1
(не рост), инъекция ×2 в окно скоринга детектируется как рост.

## Ранжирование для витрины (issue #85, фаза 3 Б3)

Классификация фраз: **растёт / сезонное / падает / стабильное**.
Растёт и падает — тот же скор факт/прогноз против симметричных порогов
(`GROWTH_RATIO_THRESHOLD` и `DECLINE_RATIO_THRESHOLD = 1/1.5`); сезонное —
амплитуда месячного профиля без тренда; остальное — стабильное. Порядок
классов в витрине: рост, сезонное, падение (сигнал сворачивать позицию),
стабильное.

Скор внутри «растёт» = веса × компоненты, все компоненты в [0, 1] и
нормируются относительно самой фразы, а не популяции — поэтому скор
фразы не зависит от соседей и ранжирование стабильно к добавлению
одной фразы (требование issue #85).

### Предрегистрация параметров (до прогона на данных)

- `DECLINE_RATIO_THRESHOLD = 1/1.5` — порог «падает», симметрично порогу
  роста: «в полтора раза реже, чем год назад».
- `SEASONAL_MAX_MIN_RATIO = 2.0` — сезонность есть, если самый сильный
  месяц месячного профиля минимум вдвое чаще самого слабого. Меньше —
  колебания неотличимы от шума стабильного ряда (высокочастотная
  фикстура ≈ 1.2, сезонная — порядка 50).
- `ANOMALY_WEIGHT = 0.5`, `VOLUME_WEIGHT = 0.3`, `FRESHNESS_WEIGHT = 0.2`
  — аномальность первична (без роста кандидата нет — половина веса),
  частотность важнее свежести («звезда» с 10 запросами не интересна
  закупке, но масштаб не главнее роста), свежесть — бонус: начавшийся
  раньше рост всё ещё рост.
- Компоненты: аномальность `1 - 1/score` (монотонна, без порога
  насыщения); объём `log10(1+частотность) / log10(1+VOLUME_TOP)`, где
  частотность — среднее обучающей истории ДО окна скоринга (базовый
  уровень ряда, а не окна: окно растущей фразы включает сам рост, и объём
  по окну коррелировал бы с аномальностью), с
  `VOLUME_TOP = 1 000 000` — верхняя планка частотности Вордстата, выше
  которой различие миллиона от двух миллионов закупке неинтересно;
  свежесть `1 / возраст роста`, возраст — длина хвоста месяцев, держащих
  порог роста (месяц ≥ 1.5 × значения год назад).

## Ниши: связка кластеров с классами трендов (issue #106)

Витрина показывает темы, а не отдельные фразы: ниша = кластер фраз
(`cluster_phrases`, #71) + доминирующий класс состава + агрегированный
скор. Выбор по п. 4 issue #106 зафиксирован в issue-комментарии: ниши
считаются ядром на основном BERTA-конвейере и фиксируются в JSON-артефакте
витрины; сборка сайта в Actions не касается extra `nlp` вовсе
(`pipeline="tfidf"` — fallback ядра для окружений без extra).

### Предрегистрация формул (до прогона на данных)

- Кластеризируются **все фразы витрины сразу**, классы агрегируются по
  составу кластера. Rationale: ниша — тема, а тема может содержать и
  растущие, и падающие фразы; кластеризация по классам порознь
  дублировала бы темы и прятала сигнал «падающая ниша» (в классе
  «падает» нет ранжирования — кластеры там вырождаются).
- Доминирующий класс ниши = мода классов состава; тай-брейк — порядок
  `CLASS_ORDER` (рост > сезонное > падает > стабильное).
- Агрегированный скор ниши = **медиана скоров фраз доминирующего класса
  состава**. Вне «растёт» скоры фраз нулевые по определению
  (`RankedPhrase`), поэтому скор таких ниш 0.0; для «растёт»-ниш медиана
  устойчивее среднего к одной аномальной фразе состава.
- Порядок ниш в артефакте: `CLASS_ORDER`, затем скор убыванием, затем
  метка-тема по алфавиту (детерминированность).

## Сезонный тайминг закупки (issue #114, фаза 6.1)

Переупаковка фаз 2–4 в календарь закупки, без нового ML: месячный профиль
ряда (тот же groupby, что в `seasonal_max_min_ratio`) → месяц пика → окно
заказа. Вордстат меряет спрос, не маржу: окно отвечает «когда заказывать,
чтобы попасть в пик», не «выгодно ли» (граница эпика #15).

### Предрегистрация формул (до прогона на данных)

- **Месяц пика** = месяц с максимальным средним месячного профиля.
  Профиль усредняет каждый календарный месяц по всей истории — разовые
  всплески сглаживаются. Тай-брейк при равных max — **меньший номер
  месяца** (детерминированность; месяц — не дата, календарь один).
- **Lead time** — параметр закупки, не прогноз: `DEFAULT_LEAD_WEEKS = 8`
  — ж/д доставка Китай→РФ, типовой путь маркетплейс-закупок. Пресеты
  (недели): `air_express=4` (авиа-экспресс, дорого, малые партии),
  `air=6` (авиа), `rail=8` (ж/д, дефолт), `sea=12` (море, дёшево,
  большие партии).
- **lead_months** = `ceil(lead_weeks / 4.348)` — средний месяц
  365.25/12/7 ≈ 4.348 недели; 8 недель → 2 месяца. Округление вверх:
  лучше заказать раньше, чем опоздать к пику.
- **Месяц заказа** = `peak_month − lead_months` (по модулю 12, 1-based).
- **Люфт** `BUFFER_MONTHS = 1`: крайний безопасный месяц =
  месяц заказа + 1 (запас на задержку поставки).
- **Успеваем или нет**: от последней точки данных до ближайшего будущего
  вхождения месяца пика считается `months_to_peak` (строго вперёд: если
  последний месяц — пик, ближайший через 12); `slack_months =
  months_to_peak − lead_months`; успеваем ⟺ `slack_months ≥ 0`.
- **Ряд без сезонности** (`seasonal_max_min_ratio < SEASONAL_MAX_MIN_RATIO`):
  окно не определяется — честный `None`/«по тренду», пик не выдумывается.
