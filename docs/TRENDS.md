# Детекция аномального роста (Фаза 3, Б1 — issue #83)

Скор аномальности месячного ряда: отношение факта последних месяцев к
прогнозу сезонного наива (`seasonal_naive`, `to_monthly_series` из
`src/wordstat_trends/forecasting/baseline.py`). Отдельная библиотека
детекции аномалий не используется — принципиальное решение проекта
(docs/REFERENCES.md, «Позиция проекта»): скор из прогноза интерпретируем,
дёшев и не тянет зависимость.

## Метод

1. Ряд фразы приводится к месячному `pd.Series` (`to_monthly_series`).
2. Хвост ряда длиной `SCORE_WINDOW` месяцев — окно скоринга; всё, что
   раньше, — обучающая история.
3. Сезонный наив обучается на истории и прогнозирует `SCORE_WINDOW`
   месяцев вперёд: прогноз месяца = значение ровно 12 месяцев назад.
4. Скор = средний факт окна / средний прогноз окна.

Скор нормирован относительно собственной истории фразы, а не популяции:
высокочастотная стабильная фраза даёт скор ≈ 1 и не является трендом,
низкочастотная растущая — кандидат.

## Предрегистрация параметров (до прогона на данных)

Объявлены до прогона на фикстурах, не подбирались по результату:

- `SCORE_WINDOW = 3` — окно скоринга в месяцах. Обоснование: 1 месяц
  шумен (разовый всплеск месяца #22 даёт ложный сигнал), окно 6+
  месяцев размывает старт роста — к моменту подтверждения рост уже
  виден и так.
- `GROWTH_RATIO_THRESHOLD = 1.5` — порог «рост есть». Сезонный наив на
  стабильном ряде даёт отношение ≈ 1; порог 1.5 означает устойчивое
  превышение фактом сезонного уровня в 1,5 раза на всём окне — на
  слуховом уровне «в полтора раза чаще, чем год назад».
- `MIN_HISTORY = 24` — минимальная длина ряда: два полных сезонных цикла,
  меньше — сезонному наиву не с чем сравнивать.

Синтетическая проверка в тестах: стабильный сезонный ряд даёт скор ≈ 1
(не рост), инъекция ×2 в окно скоринга детектируется как рост.

## Отсев ложных трендов (Фаза 3, Б2 — issue #84)

Два фильтра поверх скора детекции (`false_trends.py`). Определяющее
требование витрины (#12): показываются **долгосрочные тренды** для закупки
с циклом недели-месяцы; инфоповод в витрине — неверный ответ, а не шум.
Отсев не ослабляется ради краткосрочных всплесков #22 — это другая задача
(граница зафиксирована в докстринге `short_term.py`).

### Роль месячной грануляции — зафиксировано явно

Месячное значение Вордстата — агрегат дневных запросов за месяц: дневной
всплеск (сигнал #22, срок жизни — дни) уже погашен агрегацией и до скора
детекции не доходит. Это свойство источника используется сознательно, а не
молча: фильтр 1 ниже работает с **месячными** инфоповодами — новостью,
которая живёт недели и целиком попадает в один календарный месяц.

### Фильтр 1: разовый всплеск против устойчивого роста

Скор детекции — отношение средних по окну, поэтому один аномальный месяц
с достаточной амплитудой поднимает среднее окна за порог `GROWTH_RATIO_THRESHOLD`
— это ложноположительный случай. Критерий: месяц «подтверждает» рост, если
его собственный факт / прогноз сезонного наива для этого месяца
>= `MONTH_RATIO_THRESHOLD`; тренд требует `MIN_CONFIRMED_MONTHS`
подтверждённых месяцев из окна `SCORE_WINDOW`. Инфоповод (один месяц
выше порога) отбрасывается.

### Фильтр 2: праздничная сезонность против тренда

Сезонный наив sp=12 считает декабрьский пик нормой — сам по себе пик не
аномален. Но амплитуда пика, растущая год к году, — тренд: сезонная
компонента растёт. Критерий — сравнение амплитуды пика **год к году**
(максимум месяца последнего полного календарного года против предыдущего),
не месяца к месяцу. Структура сезонности фиксируется явно через
`ets_full_series_structure` (вывод #32: вердикту о сезонности нельзя
доверять молча) и `docs/ISSUE_32_SEASONAL_STRUCTURE.md`: пик-анализ
применяется только к рядам, у которых ETS на полном ряду выбирает сезонную
компоненту.

Фильтр применяется, когда все подтверждённые фильтром 1 месяцы лежат в
«праздничной дуге» — месяцы, чей исторический уровень
>= `PEAK_ARC_SHARE` × уровень пика. Тогда решает амплитуда пика год к
году: `PEAK_GROWTH_RATIO` и выше — тренд (амплитуда растёт), ниже —
праздничная сезонность без роста, отсев.

### Предрегистрация порогов (до прогона на данных)

Объявлены до прогона на фикстурах, не подбирались по результату:

- `MONTH_RATIO_THRESHOLD = 1.25` — месячный факт >= 1.25 × сезонного
  наива считается подтверждением. Ниже порога окна 1.5: отдельный месяц
  шумнее среднего окна, но подтверждение должно быть содержательным, а не
  следствием месячного шума стабильного ряда.
- `MIN_CONFIRMED_MONTHS = 2` — из `SCORE_WINDOW = 3`: один месяц не
  тренд, два последовательных против сезонного ожидания — минимальное
  подтверждение; три — строгое (окно целиком).
- `PEAK_ARC_SHARE = 0.5` — «праздничная дуга»: календарные месяцы с
  историческим уровнем >= половины пика. Месяцы вне дуги к пик-анализу не
  относятся: рост в несезонный месяц сезонного объяснения не имеет.
- `PEAK_GROWTH_RATIO = 1.3` — амплитуда пика последнего полного года /
  предыдущего >= 1.3 считается растущей. Ниже порога детекции 1.5: рост
  амплитуды виден на двух полных годах (компаундится), а не на одном
  окне.

Недостаток истории для пик-анализа (меньше двух полных календарных лет
вне окна) — фильтр 2 не применяется, вердикт остаётся за фильтром 1.

Синтетическая проверка в тестах: инфоповод (один месяц ×6 через порог
окна) отбрасывается фильтром 1; праздничная фраза с плоским год-к-году
пиком и аномальным текущим сезоном — фильтром 2; праздничная фраза с
растущей амплитудой проходит как тренд.
