# Стек: пакеты для временных рядов

Что берём, что не берём и почему. Раздел «не берём» здесь важнее списка
зависимостей: он показывает, что выбор осознан, а не «поставил всё, что
советуют».

Версии и даты релизов проверены по PyPI, метаданные репозиториев — по GitHub
API. Срез: **2026-08-21**.

## Python 3.12 — не 3.13

Это не вкусовщина, а следствие метаданных `sktime` 1.1.0: `statsforecast`,
`prophet` и `neuralprophet` объявлены там с ограничением
`python_version < "3.13"`.

Проверено `uv pip install --dry-run "sktime[forecasting]"` в двух чистых venv:

| Пакет | Python 3.12 | Python 3.13 |
|---|---|---|
| `statsmodels` | 0.14.6 | 0.14.6 |
| `statsforecast` | 2.0.1 | **не ставится** |
| `prophet` | 1.3.0 | **не ставится** |

Коварство в том, что **установка на 3.13 не падает** — резолвер молча
пропускает эти пакеты. `import sktime` работает, а `StatsForecastAutoETS`
роняет `ImportError` уже в рантайме, на этапе, где казалось бы всё установлено.

Отсюда два правила:

- `requires-python = ">=3.12,<3.13"` — с закрытым верхом, а не открытым.
- **Файл `.python-version` обязателен.** Без него `uv` молча берёт свежайший
  доступный Python: именно так в `wordstat-cli` venv оказался на 3.13.12 при
  системном 3.12.10.

Так и сделано в [wordstat-cli](https://github.com/axisrow/wordstat-cli/blob/main/.python-version).

## Берём

| Пакет | Версия | ★ | Лицензия | Роль |
|---|---|---|---|---|
| [sktime](https://github.com/sktime/sktime) | 1.1.0 | 9954 | BSD-3 | Ядро прогноза: единый API, бейзлайны и rolling-origin валидация в основном пакете |
| [statsmodels](https://github.com/statsmodels/statsmodels) | 0.14.6 | — | BSD-3 | Движок ETS/ARIMA под капотом sktime; STL-декомпозиция |
| [statsforecast](https://github.com/Nixtla/statsforecast) | 2.0.1 | 4875 | Apache-2.0 | Быстрые классические модели через адаптер sktime |
| [ruptures](https://github.com/deepcharles/ruptures) | 1.1.10 | 2071 | BSD-2 | **Детекция структурных сдвигов** |
| [tsfresh](https://github.com/blue-yonder/tsfresh) | 0.21.2 | 9293 | MIT | **Автоизвлечение признаков ряда** |
| [tslearn](https://github.com/tslearn-team/tslearn) | 0.9.0 | 3171 | BSD-2 | Кластеризация рядов по форме (DTW) |
| [scikit-learn](https://github.com/scikit-learn/scikit-learn) | 1.7.2 | — | BSD-3 | Классификаторы, k-means, TF-IDF-бейзлайн, метрики |

Почему именно эти четыре неочевидны:

**`sktime`, а не `darts`.** Обе хороши, но нужна не широта зоопарка моделей, а
дисциплина «бейзлайн → валидация → модель». В `sktime` сезонный наивный прогноз
(`NaiveForecaster`) и `ExpandingWindowSplitter` — часть основного API, а не
дополнение. Метрика MASE сравнивает с наивным прогнозом по построению.

**`ruptures`** закрывает задачу, которая иначе делалась бы вручную: в любом ряду
с 2018 года есть минимум три структурных сдвига — весна 2020 (COVID), весна
2022, 2024–2025 (смена методики самого Вордстата, то есть разрыв в измерениях,
а не в спросе). Сезонная модель, увидев всплеск апреля 2020, будет ждать его
каждый апрель и порекомендует закупку не в тот месяц.

**`tsfresh`** — ключ к автооткрытию трендов. Он превращает ряд в вектор из сотен
признаков (тренд, стационарность, автокорреляция, характеристики сезонности) с
отбором по статистической значимости. После этого «сезонная / растущая /
всплеск-однодневка» — обычная задача классификации для `scikit-learn`. Здесь
классический ML становится настоящим, а не просто вызовом `fit` у форкастера.

**`tslearn`** даёт вторую ось группировки: не по смыслу текста запроса, а по
форме кривой. «Товары с летним пиком» — это кластер по DTW-расстоянию, и он не
совпадает с кластером по эмбеддингам.

### Нюансы установки

Всплыли при проверке резолва, стоит учесть заранее:

- `sentence-transformers` (нужен для эмбеддингов фраз) тянет `torch` 2.13,
  около 2 ГБ. **Выносить в отдельный extra**, чтобы базовая установка
  оставалась лёгкой.
- `scikit-learn` встаёт **1.7.2**, а не последний 1.9.0: `sktime` ограничивает
  его сверху (`<1.8`). Это нормально, но объясняет расхождение с PyPI.

Отдельно: **детекция аномалий на старте не требует библиотеки вовсе.** Скор
получается из уже построенного прогноза — `факт / прогноз сезонной наивной
модели`. Это интерпретируемо, дёшево и не тянет зависимость. Специализированные
инструменты — если базовый подход упрётся.

## Смежное

- Ландшафт инструментов трендов и детекции аномалий — [docs/REFERENCES.md](REFERENCES.md).
- Лемматизация: `pymorphy3` 2.0.6 (`pymorphy2` заброшен с 2020 и ломается на
  новых Python).
- Эмбеддинги: `sergeyzh/BERTA` (0.1B, 768 dim, MIT) — дистилляция FRIDA с
  близким качеством и на порядок дешевле по CPU. Требует префиксов задач
  (`clustering:` / `categorize:`), без них качество заметно падает.

## Как перепроверить

```bash
# версия и дата релиза
curl -s https://pypi.org/pypi/ИМЯ/json | python3 -c "
import json,sys; d=json.load(sys.stdin); i=d['info']; v=i['version']
print(v, d['releases'][v][0]['upload_time'][:10], i.get('requires_python'))"

# что реально встанет на целевой версии Python
uv venv /tmp/probe --python 3.12
VIRTUAL_ENV=/tmp/probe uv pip install --dry-run "sktime[forecasting]"
```

Второй командой и была найдена ловушка 3.13: сравнить вывод на двух версиях
Python надёжнее, чем читать метаданные.
